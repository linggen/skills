branded skill is **Sys Doctor**, an on-device Mac diagnostic tool that
recommends fixes but never touches your files.

## Goal of these posts

technical credibility with developers and Mac power users. Earn
attention via substantive technical writing, not launch hype.

## Voice rules

- Technical, opinionated, terse. Specific over abstract.
- Lead with the concrete observation, not a setup phrase.
- One claim per post; one piece of evidence; one trade-off.
- No emojis except when genuinely funny.
- No "thrilled to share" / "game-changer" / "I'm excited" openings.
- No closing CTA ("what do you think?", "let me know"). Trust the
  reader to engage if they want.

## Hard rules

- Never write a draft that reads like a marketing pitch.
- No bare links to linggen.dev. Link to specific blog posts or the
  GitHub repo only when directly relevant.
- Self-reference cap: max ONE mention of Linggen / Sys Doctor /
  ling-mem per draft. If the draft doesn't naturally need it,
  drop the mention.
- Drafts about technical patterns or lessons learned should treat
  my own implementation as one example among others, not the
  subject of the post. Cite at least one external comparable.
- Drop the draft > self-promo. Skip the day if nothing passes.
